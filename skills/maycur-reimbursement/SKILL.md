# 每刻报报销填单

## 何时使用

用户要把**住宿、高铁/火车、打车、加班餐费等发票**（PDF 或截图，通常集中在一个目录）整理成每刻报（`ng.maycur.com`）报销单，并希望按公司已通过的填法逐条录入。

常见触发语：

- 「这些发票帮我报一下，目录在 `D:\xxx\发票`」
- 「上次杭州出差的住宿和高铁一起报了」
- 「加班打车报销怎么填」

**不适用**：备付金/借款申请、付款单、合同审批；纯查询历史单据（直接看「我的单据」即可，不必读本技能）。

## 发票从哪来：QQ 邮箱「发票」应用

用户的消费发票（打车、铁路、住宿、餐饮等）统一进 **QQ 邮箱**（`mail.qq.com`），落在左侧「应用 → **发票**」里。**优先从这里取发票，不要先让用户手动下载到本地目录。**

### 进入路径

```
mail.qq.com 登录 → 左侧「应用」分组 → 发票
```

侧栏另有「文件云盘 / 文件 / 中转站 / 附件管理」，发票在「文件云盘」这一组的第三项，注意别点成「附件管理」（那是全部邮件附件，噪声大得多）。

### 「发票」页结构

| 区域 | 内容 |
|---|---|
| 顶栏 | 「发票 · N」总数；「搜索发票」搜索框 |
| 工具条 | 上传发票 / **创建报销单** / 转发 / 标记星标 / **下载** / 删除 / 更多 |
| 分组 | 按月份区间折叠，如「2026年5月～10月（14 张发票）」「星标发票」 |
| 单张卡片 | 开票方、金额、**标签**（交通/餐饮/住宿等）、时间、付款方、项目；卡片前有勾选框 |

卡片信息足够直接建单，**不需要先下载再读 PDF**：

- 开票方 → 对应「往来单位」
- 金额 → 「消费金额」
- 时间 → 「消费日期」（打车只到日，不含时段）
- 付款方 → 应为 `奥琦玮科技（江苏）有限公司`，用于核对抬头
- 项目 → 如 `*交通运输服务*客运服务费`、`网上购票系统-电子发票通知`（铁路电子客票），可判断费用类型

### 「最近的 10 张」怎么取

页面本身按时间倒序，**从上往下数前 10 张**就是最近的。不要用「月份分组」当排序依据——同组内才是倒序。

若用户说「上个月的」，先用「搜索发票」框按开票方或金额筛，再按日期取。

### 下载发票原件

1. 勾选目标卡片（可多选）。
2. 点工具条「下载」。
3. **下载必须用浏览器工具的 download 动作**，指定含 `.pdf` 的目标文件名；若返回超时未完成，不要反复重试，改用人工辅助请用户手动点击「下载」。
4. 下载得到的文件保存到当前对话工作区，再由工具返回的真实路径引用，不要猜路径。

### 与本地目录的关系

用户也可能事先把发票 PDF/截图放到某个目录（如 `D:\xxx\发票`）。两种情况都要支持：

- 用户说有目录 → 先清点目录
- 用户说没整理 → 走 QQ 邮箱「发票」应用

两者冲突时以用户本轮说明为准。

### 边界

- 不读取发票内容用于报销以外的用途，不外发。
- 不删除邮箱里的发票，不勾「删除」。
- 不替用户在邮箱里「创建报销单」——那是邮箱自带的报销流程，与本技能的每刻报建单无关。

## 先确认的三件事

动手前逐条确认，缺任何一项先问用户，不要猜：

| # | 问题 | 为什么必须问 |
| --- | --- | --- |
| 1 | 这趟花费算**差旅**还是**日常费用**？ | 决定用哪种单据、要不要填行程、要不要「出差工作量化结果」 |
| 2 | 费用归属：公司抬头、承担部门、项目 | 抬头默认「奥琦玮科技（江苏）有限公司」，但项目默认「其他项目名称」，专项必须用户指定 |
| 3 | 事由（单据标题）怎么写 | 直接影响审批人判断，见「事由命名法」 |

发票文件本身能读出的信息（金额、日期、销售方、乘车人、车次/座位）不需要问。

## 选单据类型

`我的单据 → 新建单据` 弹窗按标签页分组，可选：

- **差旅费报销单** — 有异地行程：住宿、高铁/飞机、出差期间的市内交通与餐费。**一次出差 = 一张单**。
- **日常费用报销单** — 无行程或仅市内：加班餐、加班打车、办公用品（扩展坞、制冰机这类）。
- 招待费报销单 / 业务费用付款单 — 本技能不覆盖。

判定口诀：

> 发票里有**跨城市**行程 → 差旅单；两张以上交通票且日期连续 2 天以上 → 差旅单；单晚住宿但属出差 → 差旅单；其余 → 日常费用单。

同一批发票里既有出差又有加班打车，**拆成两张单**，不要混。

## 事由命名法

看历史单：事由都短、能一眼看出时间或事由性质，不要写「费用报销」「发票报销」这种零信息标题。

| 场景 | 事由写法 | 实例 |
| --- | --- | --- |
| 出差 | `<城市><事由>` | `杭州出差`、`出差交通费` |
| 加班餐饮 | `<月>月<日>加班` / `<区间>加班` | `7月8日加班`、`7.9~7.17加班` |
| 单一物品 | 物品名 | `笔记本电脑扩展坞`、`制冰机` |
| 单一用途 | 用途名 | `加班打车` |

跨多次费用合并时用区间（`7.9~7.17加班`）；一次出行用城市（`杭州出差`）。

## 差旅费报销单专有：「行程及费用」

差旅单的费用区叫**行程及费用**，以「行程」分组：

- 行程 = `<出发城市> ~ <到达城市>（往返）` + 日期区间 + 天数，例：`扬州市 ~ 北京市（往返） 2025-09-13 ~ 2025-09-15（3 天）`
- 行程内每条费用有自己的编号 `A1 / A2 / A3 …`，按日期顺序排列
- 顶部汇总：`不含税金额`、`抵扣税额`（系统按发票税额算，不需要手填）
- 分组视图可切 `按行程分组` / `列表显示`

**实际操作**：先把车票、机票按时间顺序录入，形成行程骨架；再把同一行程内的住宿、市内交通、餐费补进去。返程票不要漏——历史单里 4 条费用包含去程/改签/返程/回程接驳。

## 票据与附件规则

1. **发票走「费用明细」里的票据**，上传后系统验真，显示 `票*1 已验真`。
2. 单头「其他附件」**不放发票**，系统提示也这么写：`其他附件（如上传发票，请选择在费用明细中添加发票）`。
3. **行程单/行程截图放「其他附件」**：历史单里打车、火车都附了 `6月30行程单.pdf`、`7.8行程单.pdf`。
4. PDF 优先；截图可上传但验真可能失败，能拿到 PDF 就用 PDF。
5. 一个文件最大 50M，一单最多 30 个文件。
6. 上传前按单归类，命名 `<日期或事由>行程单.pdf`，与事由呼应。

## 查历史单（照抄同类的来源）

`我的单据 → 报销单` 页：

- 搜索框输入事由关键词（`加班打车`）或单据号，回车
- **点状态文字**（如 `已完成`）打开详情；点单据号只会复制号码
- 详情里切「单据详情」看字段，「凭证预览」看记账科目，「审批流程」看审批链
- 费用明细表是懒加载：先把页面滚到表格区域，数据才渲染

不要凭记忆填新字段，**任何不确定的选项都先查一张同类历史单**。

## 典型流程

1. **清点**：列出目录内所有发票文件，输出表：文件名 / 类型 / 金额 / 日期 / 起止地或商家。
2. **归组**：按「行程」和「日常」分组，给出单据拆分建议（几张单、每张放哪些票、事由）。
3. **确认**：把 1、2 的表格交给用户确认，同时问清归属部门和项目，以及是否愿意换票（同一行程多次打车能合并成一张）。
4. **录单**：差旅单先建行程再逐条加费用；日常单直接逐条加。
5. **自检**：金额合计 = 各票金额之和；税额合计与系统一致；每条都是 `已验真`；`报销金额 = 批准金额`（提交前）。
6. **提交前回报**：列出「单据类型 / 事由 / 条数 / 合计金额 / 附件」，等用户明确说「提交」再提交。

## 提交边界（必须遵守）

- 建单、填字段、上传、保存草稿 —— 可以在用户授权范围内执行。
- **点「提交」前必须获得用户当轮明确许可**，并复述合计金额与条数。
- 金额、抬头、部门、项目、收款账户任何一项由用户指定，不要代改。
- 识别不到发票金额/日期时，标记为「待确认」，不要猜数字。
- 发现行程缺失（例如只有去程没有返程），提醒用户，不要自行补票。

## 常见退单原因与规避

| 现象 | 原因 | 规避 |
